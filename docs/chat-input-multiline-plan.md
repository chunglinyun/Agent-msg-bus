# Chat 視窗輸入區：多行貼上與換行排版修正

狀態：**已實作（2026-07-24）**。

## Context

使用者回報（2026-07-24）兩個 chat 視窗輸入問題：

1. 輸入超過一行寬度時排版壞掉——輸入列被 DECSTBM scroll region 釘在最底列，
   readline 換行時寫出畫面外，游標數學全亂。
2. 貼上多行內容只送出第一行——readline 對貼上的每個換行各觸發一次 `line`，
   第一行被送出，其餘行被誤解析成新的「收件人 訊息」。

## 設計

兩個修正都只動 `broker.js` 的 chat 模式：

1. **Bracketed paste → 暫存代幣**：向終端機開啟 bracketed paste（`\x1b[?2004h`），
   stdin 與 readline 之間夾一個 PassThrough 攔截貼上內容。單行且**顯示寬度塞得進
   輸入區剩餘空間**的貼上直接放行（tab 轉空白，避免誤觸補全；寬度用 dispWidth
   算，CJK 一字兩欄）；多行或塞不下的貼上**不進輸入行**——內容暫存進 buffer，
   輸入行只插入 `⟦pasteN:N行⟧` 代幣，送出時展開還原原文。
   readline 因此永遠只處理塞得進輸入區的行，貼上多大都不會弄壞排版。
   副作用（好的）：貼上不再自動送出，使用者按 Enter 才送。

   （第一版用「≤200 字元」當放行門檻，字元數沒算顯示寬度：200 個 CJK 字元
   ＝400 欄 ≈ 5 列，衝出 3 列輸入區，readline 游標記帳壞掉、輸入行重複重繪
   ——2026-07-24 使用者回報後改為以顯示寬度對輸入區剩餘空間把關。）
2. **輸入區固定保留 3 列**：分隔線上移到倒數第 4 列，輸入行可以換行兩次不碰
   訊息區。送出後游標會漂移，統一走 `promptAnchored()`：重錨＋清空輸入區＋
   `rl.prevRows = 0`（readline 私有欄位，告訴它游標回到行首列）再重畫 prompt。

  第一版曾做「輸入區動態長高」（keypress 時重算列數、動 scroll region），實測
  與 readline 的游標記帳互相打架（readline 重繪從它記住的相對位置往上跳，蓋掉
  分隔線），棄用，改為固定 3 列＋大段內容走代幣。

## 邊界情況

- 終端機不支援 bracketed paste（老 conhost）：退回舊行為（逐行送出），不會更糟。
- 手打到輸入區滿：超出的字元被丟棄並響鈴（\x07），不會再壞版；控制序列
  （方向鍵、backspace、Enter）不受門檻影響。
- 代幣落在幾乎滿的輸入行上可能被截斷成半個代幣：正則不中、字面送出（ponytail
  註解，罕見到可接受）。
- 使用者砍掉半個代幣：正則不中，原字面送出，buffer 隨該行清空。
- 縮放視窗：resize handler 走 `promptAnchored(true)` 重錨重畫。

## 驗證

- 打一行超過視窗寬度的訊息：在 3 列內換行，分隔線與訊息區不壞，送出後輸入區清空。
- 貼上三行文字：輸入行顯示 `⟦paste0:3行⟧`，可在前後補字，按 Enter 後對方收到三行原文。
- 貼上 500 字單行：同樣變代幣，不會撐爆輸入區。
- 貼上 150 個中文字的單行（顯示寬度 300 欄）：塞不進輸入區 → 變代幣，不會壞版。
- 手打長字串打到輸入區滿：響鈴、字元不再進入，排版不壞。
- Ctrl+C／Ctrl+D 仍能離開；tab 補全不受影響。
- `feed` 狀態機有 assert 自檢（paste 標記跨 chunk、雙代幣、tab 轉空白）。

## 不做（YAGNI）

- 真正的多行輸入框（游標上下移動編輯）。
- 輸入區動態長高（需要對 readline 游標記帳動手術，固定 3 列夠用）。
- 非 chat 模式（`msg up` 背景 broker）完全不受影響，不動。
